## Why this device matters

The Dell Wyse 3040 is the first thin-client-class device in the census and was chosen specifically because the existing low-power registry comparison needed a third candidate from a different marketed category.

It creates useful pressure in several directions:

- it is a complete x86/amd64 computer sold as a remote-desktop endpoint rather than as a general PC;
- full Debian installation on the exact model is publicly documented;
- community OpenWrt installation demonstrates an independent headless/network-node path;
- Dell exposes UEFI USB boot, PXE, Wake-on-LAN, AC Recovery and scheduled power controls;
- Dell's own product material claims sub-4-W power consumption;
- the same marketed model exists with both 8 GB and 16 GB eMMC and optional wireless hardware, so model identity does not completely determine configuration.

That last point is an important truth constraint. A future matcher must not silently assign the best configuration of a product family to every used unit carrying the same model name.

The Debian wiki page documents a working Debian 12 installation on a Dell Wyse 3040. It records:

- 2048 MB RAM;
- Intel Atom x5-Z8350;
- four cores;
- amd64 architecture;
- internal eMMC detected and used;
- standard Debian boot/install operation after a UEFI workaround;
- a requirement to force GRUB installation to the EFI removable-media path on the documented unit;
- network-firmware caveats.

### What this proves

- full conventional Debian Linux can run on the exact model;
- internal eMMC can host the installed OS;
- the device is usable as an amd64 Linux computer beyond its original thin-client role.

### What this does not prove

- identical behavior across every BIOS revision;
- that every optional wireless module works without firmware setup;
- long-duration service reliability;
- AXM local reproduction.

The UEFI workaround is operational friction and belongs in the real-cost model rather than being hidden because installation eventually succeeds.

- eMMC can be reimaged from USB-booted Linux;

### What this does not prove

- current upstream OpenWrt support as a first-class official target for this exact device;
- that the old build recipe is the best present-day deployment method;
- local AXM reproduction.

For the current registry comparison, Debian is the cleaner general-purpose baseline; OpenWrt is supporting evidence that the box is not tied to the vendor thin-client OS.

- PXE boot over IPv4/IPv6;
- USB boot from attached storage;
- BIOS restore-default and factory-default options;
- explicit USB boot enable/disable controls for Wyse 3040.

### Recovery interpretation

The strongest grounded recovery paths currently are:

```text
installed Linux / damaged userspace
  -> boot known-good USB media
  -> reinstall Debian to eMMC
  -> system/application/user state on the target installation is recreated

misconfigured BIOS
  -> restore BIOS factory defaults
  -> firmware configuration returns toward Dell factory state
```

These paths do **not** prove recovery from:

- physically failed eMMC;
- a failed low-level BIOS firmware flash;
- motherboard failure;
- every class of corrupted UEFI state.

## Configuration-identity lesson

The Wyse 3040 exposes a schema issue that is easy to miss in second-hand hardware research:

```text
exact model identity
  !=
exact purchasable-unit configuration
```

Dell documents both 8 GB and 16 GB eMMC and optional wireless hardware under the same model family.

For arbitrage work this matters because a market listing that says only `Wyse 3040` does not prove:

- 8 GB vs 16 GB storage;
- WLAN/Bluetooth presence;
- the same original OS image entitlement/configuration.

A future market collector should therefore preserve observed unit configuration or mark it unknown rather than normalizing every listing to the best-known variant.

## Fit against `low-power-local-registry-node`

Current evidence gives the Wyse 3040 a strong preliminary fit:

- custom Linux execution: yes, community-verified;
- RAM >= 64 MB: yes, 2 GB documented;
- persistent state: yes, 8/16 GB eMMC family documented;
- local networking: yes, Gigabit Ethernet documented;
- unattended boot potential: AC Recovery/auto-on controls documented;
- cloud-required runtime: no for self-installed Debian/OpenWrt;
- recovery path: USB boot/reinstall documented/community-verified;
- preferred average power <= 10 W: manufacturer claims <4 W, but workload measurement is still missing.

The record must **not** yet call the device the winner because the comparison still lacks:

- dated NL/EU used-market samples;
- setup/provisioning time;
- wall-power measurement under the same registry workload used for other candidates;
- exact unit configuration and eMMC health;
- replacement availability;
- hard-power-loss service-autostart verification.

## Root gate

**Truth:** exact-model manufacturer specs and community Linux execution are separated; configuration variants and measurement gaps remain explicit.  
**Agency / non-domination:** installation/reimaging applies only to owned or explicitly authorized units.  
**Continuity:** sources, UEFI friction, recovery semantics and configuration caveats live in repository state.  
**Wisdom before speed:** the device becomes a comparison candidate, not a winner, until market, power, provisioning and restart evidence exist.
